# 版本与发布

## 更新顺序

1. 在对应私有仓库提交修改并通过 CI。修改业务桥接口时，同时验证 Web 和 NapCatBot 的跨仓测试。
2. 在 HIVESOC 更新三个 gitlink 和 `versions.lock.json`，记录经过验证的准确提交。公开 CI 只核对版本结构，不下载私有源码。
3. 在对应私有仓库手动运行 `Deploy production`，指定主仓库锁定提交及当前生产版本。发布入口重新运行验证，拒绝分支不匹配、过期包、重复请求、错误基线和签名不合法的包。
4. 服务器持有发布锁，先备份、构建不可变目录，再原子切换并检查服务。失败时切回上一代码版本；不自动恢复旧数据库覆盖期间新增记录。

发布工具、密钥配置和恢复操作详见私有组件仓库中的运维说明。公开仓库不保存服务器地址、私有构建产物或生产执行回执。

## 范围

Web 发布可以更新网站后端、构建后的静态页面和更新公告。由 root 执行的备份/状态脚本、服务配置、环境变量和发布程序不接受普通应用发布覆盖；依赖变化需要单独维护环境。

NapCatBot 发布只针对 Carrot 的已批准源码覆盖层。QQ 登录、NapCat、Kona、Minecraft、Hermes 独立运行时、环境配置与业务数据不在普通发布范围。算法仓库尚无生产服务，不提供会重启机器人的空发布流程。

维护性迁移不添加虚假的产品更新公告。新增网站功能仍按 Web 仓库中的公告门禁要求发布。

## 私有仓访问

CI 的跨仓读取使用单仓只读部署密钥。生产发布使用专用受限 SSH 密钥及独立签名密钥；不复用个人 root SSH 私钥、不存放个人 GitHub OAuth token。替换这些密钥时同步更新 GitHub secrets 和服务器可信公钥，移除旧授权后执行受限发布验证。
